# Coding

1. Think before coding — state assumptions, surface tradeoffs, push back when warranted. Don't silently pick one interpretation of an ambiguous request and run with it.

2. Simplicity first — minimum code that solves the problem, nothing speculative. Avoid unnecessary abstractions, don't overengineer.

3. Surgical changes only — modify only what the request requires. Don't "improve" adjacent code, rewrite whole files, or clean up things nobody asked about.

4. Verifiable success criteria — define what "done" looks like in testable terms before executing, then loop until it's met.
